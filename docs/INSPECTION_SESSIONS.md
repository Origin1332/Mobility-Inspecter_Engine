# 검사 세션 사용법 (0.4.0)

사진과 AI 원본 결과를 보존하고 사용자 수정·품번 후보·메모를 연결해 기기에서 저장/재열기한다. 실제 저장은 오프라인 웹 검사 화면의 IndexedDB를 사용한다. 서버 전송과 자동 학습 반영은 없다.

## 사진 검사

1. **오프라인 웹 검사**에서 사진을 선택하고 **부품 탐지**를 실행한다. 모델 없이 사진에 수동 박스를 추가하는 것도 가능하다.
2. 박스/부품 목록에서 선택 후 **부품·좌표 수정**으로 클래스와 좌표를 수정한다. 좌표는 화면에서 사용하는 축소 사진의 픽셀 기준이다.
3. 오탐은 **오탐 제외**로 제외한다. **제외한 박스 표시**를 켜고 선택하면 제외를 취소할 수 있다.
4. 미탐은 **누락 박스 그리기**를 누르고 사진 위를 드래그한 뒤 부품 종류를 선택해 추가한다.
5. **연결된 품번·부속 보기**에서 원문과 옵션을 확인한 후 **검사 품번 후보로 선택**을 누른다. 선택은 장착 적합성 확정이 아니다. 필요하면 **선택 품번 해제**를 사용한다.
6. 검사 이름과 메모를 입력하고 **검사 저장**을 누른다. **기기 저장 완료** 표시를 확인한다.
7. **저장된 검사**에서 사진과 원본/수정 결과를 다시 연다. 같은 검사를 다시 저장하면 같은 ID의 기록을 갱신한다.

새 사진 열기, 다른 검사 열기, 재추론 시 변경 사항 유실 여부를 확인한다. 재추론은 현재 박스 수정과 품번 선택을 새 결과로 교체한다. 저장 실패 시 성공으로 표시하지 않고 화면의 수정 사항을 유지한다. 앱 강제 종료 전 자동 저장은 제공하지 않으므로 명시적으로 저장한다.

## 실시간 장면 검사

Android 메인 화면에서 모델을 준비하고 **실시간 카메라 → 장면 고정·검사**를 누른다. 표시 중이던 사진과 그 프레임의 박스·모델 정보·임계값을 함께 고정하여 웹 검사 화면으로 연다. 네이티브 추론 결과를 그대로 전달하며 자동으로 재추론하지 않는다. 사용자는 확인·수정 후 저장한다.

돌아오면 카메라는 일시정지 상태이며 **일시정지/재개**로 재개한다. 웹 카탈로그 저장소는 네이티브 검수 팩과 공유되지 않으므로 웹에서 카탈로그 팩을 한 번 가져와야 한다. 이 기능은 기존 카메라 미리보기 구조나 프레임 추적을 변경하지 않는다.

## 보존 규칙

- `original`: 사용자가 수정하기 전 AI 출력의 별도 복사본. 네이티브는 당시 임계값을 통과한 박스이며, 웹은 점수 하한/NMS 이후 결과다. 모델의 원시 텐서 전체를 보관하는 것은 아니다.
- `reviewed`: 현재 사용자 작업 결과. 박스별 `origin`은 `ai`, `corrected`, `manual`이다.
- 클래스/좌표가 수정되면 `score`를 null로 바꾸고 사용자 수정으로 표시한다. 기존 AI 점수는 `original`에 남는다. 수동 박스에 AI 점수를 생성하지 않는다.
- 오탐은 삭제 대신 `excluded`로 표시한다. 클래스 변경 시 기존 품번 선택을 해제한다.
- 선택 후보에는 품번/이름/옵션/기간/원문 페이지/행 ID/카탈로그 해시를 남긴다. 이후 다른 카탈로그를 가져오면 출처 차이를 표시한다.
- 원본 업로드 Blob과 표시용 축소 JPEG, 검사 이름·메모·시각·모델 정보·임계값·앱 버전을 함께 저장한다. 카메라 원본은 고정 프레임의 JPEG다.
- 사진과 메타데이터는 같은 IndexedDB 트랜잭션으로 저장한다. 모델을 바꿔도 이미 열린 검사의 모델 정보는 바뀌지 않는다.

## 내보내기 및 제한

검사 JSON은 `schema_version: 2`, `record_type: engine_inspection_session`이다. v0.3의 단일 탐지 JSON과 구조가 다르다. `original`과 `reviewed`를 구분해서 읽어야 하며 제외한 박스도 내보내기에 남는다. 소비자는 `excluded`를 반영해야 한다.

**JSON 내보내기는 사진을 포함하지 않는 메타데이터 출력이다.** 사진 포함 외부 백업/복원, JSON 가져오기, 검사 삭제, 검사별 수정 이력 전체 기록, 사용자 수정의 자동 학습 반영은 이번 버전에 포함하지 않는다. 기기 앱/사이트 데이터를 삭제하면 검사 사진과 기록도 삭제된다. 학습용 정답으로 사용하려면 별도 검수가 필요하다.

## 검증

- 웹 단위 검사: 원본 불변, 수정 시 점수/품번 처리, 수동 박스/좌표 검증, 제외 상태 내보내기, 구조화 복제 후 사진/메모/수정 결과 보존, 잘못된 기록 거부.
- 기존 웹/데이터/카탈로그 회귀 검사 및 웹 빌드 수행.
- 구조화 복제 검사는 실제 IndexedDB 영속성 시험을 대신하지 않는다. 실제 기기에서 저장→앱 종료→재열기, 저장 공간 부족, 화면 회전/뒤로 가기, 카메라 프레임 전달, 터치 박스 그리기는 추가 검증 대상이다.
- 브라우저 미리보기의 일반 HTTP 원점에서는 기존 보안 컨텍스트 제한 때문에 전체 실행을 검증할 수 없다. 보안 제한을 완화하지 않는다.
